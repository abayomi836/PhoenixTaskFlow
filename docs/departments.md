# Department API Documentation

## Overview

The Department API manages the departments available in PhoenixTASKFLOW. Departments are used to organize employees and tasks within the system.

Department management is restricted to administrators, while authenticated users can retrieve department information.

## Department Model

A department contains the following fields:

| Field | Type | Required | Description |
|---|---|---|---|
| `_id` | ObjectId | Yes | Unique identifier generated by MongoDB |
| `name` | String | Yes | Name of the department |
| `description` | String | No | Description of the department |
| `isActive` | Boolean | No | Indicates whether the department is active |
| `createdAt` | Date | Automatic | Date the department was created |
| `updatedAt` | Date | Automatic | Date the department was last updated |

The `isActive` field defaults to `true`.

## Authentication

All Department API endpoints require authentication.

Protected requests must include a JWT in the request header:

```text
Authorization: Bearer <token>

Only users with the admin role can create, update, or deactivate departments.

Endpoints
1. Get All Departments

Endpoint

GET /api/departments

Access

Authenticated users.

Description

Retrieves all departments.

Successful Response

{
  "success": true,
  "message": "Departments retrieved successfully",
  "data": []
}

2. Get a Department by ID

Endpoint

GET /api/departments/:id

Access

Authenticated users.

Description

Retrieves a specific department using its ID.

Successful Response

{
  "success": true,
  "message": "Department retrieved successfully",
  "data": {
    "_id": "DEPARTMENT_ID",
    "name": "Academic",
    "description": "Academic and teaching activities",
    "isActive": true
  }
}

If the department does not exist:

{
  "success": false,
  "message": "Department not found",
  "data": null
}

Create a Department

Endpoint

POST /api/departments

Access

Admin only.

Request Body

{
  "name": "Finance",
  "description": "Financial and accounting activities"
}

Successful Response

{
  "success": true,
  "message": "Department created successfully",
  "data": {}
}

The department name is required.

A department with an existing name cannot be created.

If the department already exists:

{
  "success": false,
  "message": "A department with this name already exists",
  "data": null
}

Update a Department

Endpoint

PATCH /api/departments/:id

Access

Admin only.

Request Body

{
  "name": "Finance and Accounts",
  "description": "Financial and accounting activities",
  "isActive": true
}

All fields are optional when updating a department.

Successful Response

{
  "success": true,
  "message": "Department updated successfully",
  "data": {}
}

If the department does not exist:

{
  "success": false,
  "message": "Department not found",
  "data": null
}
5. Deactivate a Department

Endpoint

DELETE /api/departments/:id

Access

Admin only.

Description

The DELETE endpoint does not physically remove the department from the database. Instead, it sets isActive to false.

This allows the department record to remain available in the database while preventing it from being treated as an active department.

Successful Response

{
  "success": true,
  "message": "Department deactivated successfully",
  "data": {}
}
Validation

The Department API validates incoming data before processing requests.

For department creation:

name is required.
name cannot be empty.
description is optional.

For department updates:

name is optional but cannot be empty when provided.
description is optional.
isActive must be a boolean when provided.

Validation failures return HTTP 400.

Example:

{
  "success": false,
  "message": "Validation failed",
  "data": [
    {
      "type": "field",
      "value": "",
      "msg": "Department name is required",
      "path": "name"
    }
  ]
}
Authorization

Department operations are protected by role-based authorization.

Operation	Employee	Manager	Admin
View departments	Yes	Yes	Yes
View department by ID	Yes	Yes	Yes
Create department	No	No	Yes
Update department	No	No	Yes
Deactivate department	No	No	Yes

Unauthorized users receive HTTP 403.

Example:

{
  "success": false,
  "message": "You are not authorized to perform this action",
  "data": null
}
Error Handling

The API uses centralized error handling for unexpected server errors.

Unexpected server errors return HTTP 500:

{
  "success": false,
  "message": "Something went wrong on the server",
  "data": null
}
Testing

The Department API was tested using Postman.

The following scenarios were tested:

Retrieve departments successfully.
Create a department as an administrator.
Attempt to create a department as an employee.
Update a department.
Deactivate a department.
Attempt to create a department with an empty name.
Attempt to create a duplicate department.
Access protected endpoints without authentication.

The tests confirmed authentication, role-based authorization, validation, department creation, retrieval, updating, and deactivation.
